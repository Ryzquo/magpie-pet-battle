# Magpie 宠物对战

## 职责与入口

插件提供 Magpie 侧栏大厅和一对一房间。从 `magpie-digital-pet` 的 SQLite 存档读取当前出战宠物，读取适配器只依赖 v0.6.0 的存档结构。对战结果保留在房间内，不写回宠物成长数据。

局域网模式由插件自行发布和接收发现信息，玩家主动开启发现后才公布出战宠物摘要。发起者主持房间，受邀方接受后通过发起者的服务加入。对战码模式由各客户端访问同一个独立房间服务。房间服务与局域网房主运行同一个结算模块。

## 生命周期

发起局域网挑战时临时创建房间，发起方留在大厅，受邀方占座后才切换到房间。互相挑战时按发现标识确定唯一可接受的邀请，加入后关闭另一间临时房间。取消或过期会关闭尚未加入的临时房间。

本机页面服务处理发现开关、邀请和当前房间链接；页面刷新可重新读取同一插件进程的状态。进入房间时保存宠物摘要及默认配装。等待阶段允许提交配装，双方可查阅对方配装；各自准备后锁定。结算方验证属性预算、技能资格、能量和冷却，双方锁定或到达截止时间后同时结算。轮次或生命条件满足时确定结果。房间与凭据仅存内存，等待房间和闲置房间会过期。

## 关键不变量

- 每个席位使用独立凭据，对战码只用于加入。等待阶段最多允许两人占座。
- 本回合结算前，客户端只能观察双方是否已经锁招。过期轮次的行动不得应用到下一回合。
- 两种入口使用相同的战斗规则。图鉴种类决定等预算基础属性的分布，养成进度无额外预算。生命和伤害由配装及回合效果决定。
- 局域网发现协议及房间 HTTP 路径随不兼容的战斗规则一起升级，避免不同规则的客户端混局。

## 验证标准

双端分别验证局域网发现、挑战与接受，以及共享房间服务下的输码加入。两种入口都应完成准备、出招与结算，覆盖掉线恢复、超时及关闭房间。侧栏需验证 Magpie 插件宿主能加载页面并读取配置指定的存档。
